# UI_Unilineal V0.4 — Dedicated Board Detail Spike

## Hipótesis

El unilineal resumen y el unilineal detallado cumplen funciones
diferentes y no deben competir por el mismo espacio permanente.

## Diseño probado

### Resumen

Permanece como vista principal del proyecto:

- empalme;
- TGBT;
- tableros derivados;
- relaciones jerárquicas;
- edición ficticia de layout/topología.

### Inspector lateral

Se reduce a información compacta:

- código;
- nombre;
- UID;
- alimentación;
- cantidad de circuitos;
- protección general;
- primeras ramas.

Incluye `Abrir unilineal del tablero`.

### Detalle dedicado

Al abrir un tablero:

- el resumen se oculta temporalmente;
- el tablero ocupa el workspace principal;
- aparecen controles Volver, Zoom +, Zoom -, Fit;
- el ScrollViewer permite desplazamiento;
- se reutiliza `RicBoardDetailPrototypeControl` de V0.3.

## Objetivo del spike

Responder:

1. ¿Resumen + inspector compacto es suficiente para navegar?
2. ¿El detalle dedicado permite leer naturalmente tableros con más
   circuitos?
3. ¿Volver / zoom / fit forman una navegación adecuada?
4. ¿Esta estructura merece convertirse en arquitectura real?

## Restricciones

- No modifica `UI_Unilineal.Domain`.
- No modifica `UI_Unilineal.Engine`.
- No modifica ProyectoElectrico.
- No persiste layout ni topología.
- No constituye cumplimiento RIC 18.
- El renderer sigue siendo código de spike.
- La implementación puede descartarse completamente.

## Criterio de cierre

Si la navegación V0.4 resulta natural, se detiene la serie de spikes.

El siguiente paso será diseñar e implementar con TDD:

- `SingleLineInput`;
- `EntityUid` / `EntityReference`;
- `SupplyConnection`;
- `SingleLineProjection`;
- `DiagramScene`;
- perfil RIC18;
- renderer Avalonia real.
