# UI_Unilineal V0.3 — Board Detail RIC-like Spike

## Objetivo

Validar si la vista detallada de un tablero funciona mejor como
diagrama unilineal gráfico que como inspector vertical de datos.

V0.3 mantiene sin cambios conceptuales el resumen jerárquico de V0.2.

## Rama

`spike/v0.3-board-detail-ric`

## Alcance

Se incorpora un control experimental:

`RicBoardDetailPrototypeControl`

El control representa:

- alimentación del tablero;
- protección general;
- barra principal;
- derivaciones de circuitos;
- protección termomagnética;
- protección diferencial;
- carga o tablero derivado;
- referencia preliminar de puesta a tierra;
- estados `POR DEFINIR`.

## Clasificación normativa

Esta V0.3 NO afirma cumplimiento gráfico completo con RIC 18.

Se utiliza la separación conceptual acordada:

- `RIC18_REFERENCE`: estructura visual inspirada en el ejemplo y
  requisitos del RIC 18;
- `APP_CONVENTION`: coordenadas, distancias, tamaños y composición
  preliminar elegidos por UI_Unilineal.

## Restricciones

- No modifica `UI_Unilineal.Domain`.
- No modifica `UI_Unilineal.Engine`.
- No persiste cambios.
- No modifica ProyectoElectrico.
- Usa fixtures ficticios.
- No es renderer de producción.
- Puede descartarse completamente.

## Preguntas que debe responder V0.3

1. ¿El detalle se entiende como un unilineal y no sólo como una ficha?
2. ¿La jerarquía alimentación → protección → barra → circuitos resulta
   natural?
3. ¿Es útil representar tableros derivados directamente al final de una
   rama?
4. ¿Qué datos deberían mostrarse siempre y cuáles deberían ir en
   tooltip/detalle?
5. ¿El resumen y el detalle pueden convivir en la misma pantalla o el
   detalle debería ocupar un canvas completo al abrir un tablero?

## Salida esperada

Las conclusiones de V0.3 servirán para diseñar posteriormente:

- `SingleLineInput`;
- `SingleLineProjection`;
- catálogo RIC18;
- `DiagramScene`;
- renderer Avalonia real.

Nada de este spike se considera automáticamente código definitivo.
